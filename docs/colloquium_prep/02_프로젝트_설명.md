# 02. 프로젝트 설명 — 처음 듣는 사람에게 단계별로

> 길이별 설명(한 문장 → 30초 → 3분 → 전체)과 P-D-A-V 흐름, 핵심 수치 카드, 설계 결정의 이유를 정리했다.
> 개념 설명은 `01_기초지식.md`, 질문 대응은 `03_예상질문.md`.

---

## 1. 한 문장

> **원격 운전자가 보는 카메라 6대 중 "지금 봐야 할 화면"을 AI가 골라 강조해 주는 시스템이며, 정답 데이터가 없어서 공개 자율주행 데이터로 정답을 자동으로 만들어 학습·검증했습니다.**

## 2. 30초 버전

> 원격 운전자는 차 밖에서 카메라 영상만 보고 운전합니다. 화면은 6개인데 정말 봐야 할 위험은 전체 시간의 13%에서만 생깁니다.
> 그래서 진행 방향 화면은 항상 보여 주고, 나머지 5개 중 지금 중요한 화면만 0~2장 골라 강조하는 모델을 만들었습니다.
> 이런 정답 데이터가 세상에 없어서 nuScenes의 3D 정답과 차량 신호로 정답을 자동 생성했고, 평균 0.47장만 켜서 위험의 96%를 화면에 담았습니다.
> 실제 검출기는 불완전하므로 입력을 일부러 망가뜨려 학습했고, 같은 정보만 쓰는 규칙보다 사람 판단과 14~17%p 더 일치했습니다.

## 3. 3분 버전의 뼈대 (P-D-A-V)

과목 평가 관점은 "모델 성능이 아니라 **Problem → Data → AI → Action → Value**의 연결"이다.

| 단계 | 핵심 내용 | 근거 수치 |
|---|---|---|
| **P 문제** | 원격 운전의 상황인식은 영상에서 나온다. 화면을 더 띄운다고 나아지지 않고, 상황에 맞춘 표시는 효과가 있다. 그런데 **어느 카메라를 언제 강조할지**는 아무도 다루지 않았다 | 위험 프레임 13.2%, 항상 1장 강조 시 정밀도 4.7% |
| **D 데이터** | 공개 정답 없음 → nuScenes 3D GT·CAN·지도로 '봐야 할 화면' 의사 라벨 자동 생성 | 34,149장, 평균 0.47장으로 위험 96.3% 포착 |
| **A AI** | 영상 + CAN + 위험도를 Transformer로 섞고 GRU로 시간 처리, 검출 오류로 증강 학습한 0.46M 경량 모델 | 과거 2초만 입력 |
| **Action** | 진행 방향은 항상, 보조 뷰 0~2장을 하이라이트(6채널은 모두 유지) | 볼 것이 없으면 0장(61.9% 프레임) |
| **V 가치** | 같은 표시량에서 규칙과 대등한 위험 포착 + 같은 정보 조건 규칙보다 사람 판단과 더 일치 | 93.8% vs 94.3~96.0%, Top-1 63.3% vs 51.1% |

**V는 "주의 배분" 지표로만 주장한다** — 대역폭 절감, 1인 다차량, 실제 인지 부하 감소는 측정하지 않았다.

## 4. 전체 설명 — 이야기 순서대로

### 4.1 무엇이 문제인가
1. 자율주행차는 모든 상황을 스스로 풀지 못한다(Goodall 2020, Tener & Lanir 2022). 그 공백을 사람이 원격으로 메우는 것이 **원격 운전**이고, 상용화의 필수 요소로 꼽힌다(Zhao et al. 2024).
2. 원격 운전자는 차와 떨어져 있어 **상황인식이 낮고**, 그 상황인식은 주로 **영상**으로 만들어진다(Wolf et al. 2025).
3. 그런데 **영상을 더 띄워도 나아지지 않는다** — 버드아이 뷰를 추가해도 상황인식이 그대로였다(Boker & Lanir 2023).
4. 반대로 **표현을 상황에 맞추면 효과가 있다** — 카메라 시점 변경만으로 과업 시간 14%↓(Musicant 2024), 동적 GUI가 고정 GUI보다 우수(Wolf 2025), 위험 표시가 지각을 돕는다(Srinivasan 2024).
5. 그러나 **어느 카메라를 강조할지**를 상황에 따라 고르는 연구는 없고 공개 벤치마크도 없다.
6. 그리고 그 판단은 자명하지 않다 — 실제 위험은 프레임의 **13.2%**에서만 생기고, 항상 한 화면을 강조하면 **정밀도가 4.7%**(대부분 헛강조)다.

### 4.2 무엇을 만들었나 — 시스템의 출력 형태
- **진행 방향 화면(primary)**: 전진이면 전방, 후진이면 후방 — **항상 표시**, 예측 대상이 아니다(이동체 안전 원칙).
- **보조 뷰(auxiliary)**: 나머지 5개 중 **0~2장**을 강조. 볼 것이 없으면 0장.
- **하이라이트 방식**: 6개 화면은 모두 계속 보이고, 선택한 화면에 테두리 등으로 강조만 한다. 놓쳐도 정보는 화면에 남아 있다(=주의 유도 실패이지 안전 실패가 아님). 화면을 끄는 '전환 방식'은 "검출이 불완전하다"는 전제와 모순이라 기본 가정으로 쓰지 않았다.

### 4.3 기여 ① — 의사 라벨 자동 생성
"봐야 할 화면"의 정답을 사람이 3만 장에 달 수는 없다. 그래서 규칙으로 만들었다.
1. **객체 → 화면**: 3D 정답 박스를 6개 카메라에 투영해 보이는 화면에 배정.
2. **위험도**: 객체마다 **최접근 TTC와 DCA**를 계산(반경 방향 TTC는 길가 주차 차량을 위험으로 오판 → 위험량의 62.9%가 정지 객체였다). 상태(주차·정지) 계수, 경로 관련성 계수, 진행 방향 근접 보정을 곱해 가중치 w → 화면별로 합산해 EMA 평활.
3. **기동**: 지도의 차로·교차로 정보와 [−1, +5]초 궤적으로 7가지 기동을 판정. 미래 5초를 보므로 **"곧 할 기동"**을 라벨에 담는다(선제적 전환).
4. **역할 분리 슬롯**: 슬롯 1 = 기동이 만드는 사각지대(검출과 무관하게 켬), 슬롯 2 = 위험도 ≥ 0.12인 화면.
5. **검증**: 사람 검수 2회 + 방향지시등(라벨에 안 씀) 일치 좌회전 73.9%·우회전 67.2% + 골드셋 Top-1 73.3%.
6. **결과**: 평균 **0.47장**으로 위험 **96.3%** 포착(정밀도 10.6%) — 항상 1장(94.2%, 4.7%)보다 **53% 적게 켜고 더 많이 잡는다.**

### 4.4 기여 ② — 학습 모델 (왜 규칙을 그대로 쓰지 않나)
- 라벨 규칙은 **미래 5초 궤적**을 본다 → 운용 중에는 쓸 수 없다. 과거만 보는 규칙(B2c)으로 바꾸면 기동 장면에서 사람 판단 일치가 95.7% → 54.3%로 무너진다(골드셋 기동 층).
- 또 라벨 규칙은 **GT 박스**를 쓴다 → 실제로는 불완전한 검출기 결과가 들어온다.
- 그래서 **과거 2초의 영상·CAN(지시등 포함)·손상된 위험도**만으로 라벨을 흉내 내도록 학습했다. 모델이 과거 단서(지시등, 감속, 조향 시작)에서 **곧 할 기동을 읽어 내는 것**이 학습의 존재 이유다.
- 구조: 화면 6개 + CAN 1개 토큰 → Transformer(화면 간 관계) → 화면별 GRU(시간) → 화면별 시그모이드(0~2장). 0.46M 파라미터.
- 학습 시 누락·오검출·위치 오차·카메라 고장을 **epoch마다 다르게** 주입.

### 4.5 기여 ③ — 평가 설계 (순환 평가를 피하는 법)
- 의사 라벨로 채점하면 라벨을 만든 규칙이 정의상 만점 → **의미 없음**.
- 그래서 잣대를 두 개 따로 세웠다:
  1. **위험 포착률** — GT 기하로 직접 계산, **같은 표시량(0.48장)**에서 비교(많이 켜는 쪽이 이기는 착시 제거).
  2. **사람 골드셋** — test 분할에서 위험 100 / 기동 100 / 무작위 100 층화 추출, 연구자가 라벨·모델 답을 가린 UI로 직접 판정(285장 완료, 강조할 화면이 있는 장면 90장).
- 모든 방법(규칙 포함)이 **같은 손상 입력**을 보도록 프레임 단위 시드를 맞췄다.

### 4.6 결과 — 세 가지 주장과 증거

**주장 1. 의사 라벨 생성이 동작한다**
- 0.47장으로 위험 96.3%, 항상 1장보다 표시량 53%↓·정밀도 2.3배.
- 사람 판단과 Top-1 73.3% / Top-2 88.9% 일치(비가중 90장).
- 단, 사람이 '강조 불필요'로 본 장면의 54%(비가중; 가중 환산 32.7%)에서 라벨이 화면을 켠다 → **위험 정의가 사람 기준보다 넓다**(사람은 위험이 이미 전방 화면에 보이면 측방을 강조할 필요를 못 느낀다).

**주장 2. 다중 신호 융합 + 시간 모델이 필요하다**
| 비교 | 같은 표시량 포착률 | Flicker | 골드 Top-1 |
|---|---|---|---|
| 제안 | 93.8% | 0.52 | 63.3% |
| B3 영상만 | 72.9% (−20.8%p) | 0.61 | 54.4% |
| B4 단일 프레임 | 90.1% (−3.7%p) | 0.77 | 68.9% |

(Flicker는 같은 표시량 0.48장에서 보간한 값 — 논문 표 2와 같다. 규칙 B2·B2c는 0.54·0.53으로 제안과 거의 같다.)
- Ablation: 위험도 제거 −20.0%p(가장 큼), GRU 제거 −3.8%p & flicker 0.76, 시간 일관성 항 제거 −1.5%p, CAN 제거 −0.6%p, cross-view attention 제거 ±0.0%p.
- 정직한 해석: 시간 모델은 **안정성과 위험 포착**을 개선했지만, **사람 기준 Top-1 향상은 확인되지 않았다**(B4 68.9% > 제안 63.3%, 차이는 유의하지 않음 p=0.383).

**주장 3. 불완전한 입력에서 같은 정보 조건의 규칙보다 사람과 더 일치한다 (최중요)**
- clean + 네 가지 heavy 손상 **모든 조건**에서 골드 Top-1이 B2c보다 **14.4~16.7%p 높다**.
- 위험 포착률 차이는 −2.6~−0.2%p로 **대등**(규칙이 근소하게 높음).
- 손상에 따른 하락 폭은 제안 −3.3~+1.1%p, B2c −5.6~0%p로 **차이 없음** → 강건성은 "기울기"가 아니라 **"수준" 차이**로 서술(2026-10-13 결정).
- 짝비교(noisy-medium, 90장): 제안만 맞힘 22 / B2c만 11, **McNemar p = 0.080** — 경향이며 5% 유의는 아님.
- 원래 가설("열화가 더 완만하다")은 **확인되지 않았다**는 것을 숨기지 않는다.

### 4.7 흥미로운 관찰 (논의거리)
- **위험도 입력을 뺀 A2가 사람 판단과 가장 잘 일치했다(Top-1 74.4%)** — 위험 포착률은 74%로 크게 떨어지는데도. 사람은 위험 객체보다 **"곧 갈 방향"**을 기준으로 화면을 고른다. → 위험 포착과 사람 일치는 서로 다른 목표이며, 라벨에 진행 의도를 더 반영해야 한다는 향후 과제로 이어진다.
- **골드셋 위험 층에서는 모든 방법이 40~56%**: 위험이 있는 장면에서도 사람은 위험 객체가 있는 화면 대신 다른 화면을 고르는 경우가 많았다(위험이 이미 전방에 있으면 측방은 필요 없다는 판단).
- **카메라 3대 고장**에는 모든 방법이 포착률 17%p 이상 떨어진다 — 영상도 검출도 함께 사라지므로 어떤 방법도 못 본다. 공통 약점.
- **전방 화면만으로 위험의 59.0%가 보인다**(B1) → 보조 뷰가 담당하는 건 나머지 41%.

### 4.8 한계 (먼저 말하는 게 낫다)
1. **오프라인 검증만** — 실제 오퍼레이터의 주의·인지 부하·운전 수행은 측정하지 않았다.
2. **골드셋 판정자 1명(연구자 본인)** — 판정자 간 일치도 없음. UI에서 라벨·모델 답을 숨겨 편향을 줄였다.
3. **골드셋 규모** — 정답 있는 장면 90장, 신뢰구간이 넓다. 핵심 비교 p=0.080.
4. **차선변경 희소(258프레임, 0.8%)**, **후진 평가 불가**(8프레임 전부 train 분할).
5. **위험도 입력은 GT + 시뮬레이션 오류** — 실제 검출기를 붙이지 않았다.
6. **nuScenes 한정** — 맵 확장은 nuScenes 전용, 지역 단위 일반화는 시험하지 않았다.
7. 위험 포착률은 규칙을 **넘지 못했다**(대등).

### 4.9 향후 계획
1. 사람의 주의 기준(진행 의도, 잠재 위험)을 라벨에 반영.
2. 카메라 고장 같은 채널 결손을 학습으로 보강.
3. 실제 검출기 출력으로 교체, 다중 판정자 골드셋.
4. 시뮬레이터/실차 오퍼레이터 실험으로 주의 배분 효과 검증.

## 7. 개발 과정에서 고친 것 (정직성·엄밀성을 보여 주는 이야기)
- **방향지시등 점멸 버그**: CAN 값이 레버가 아니라 램프 점멸이라 켜진 프레임의 49.6%를 꺼짐으로 읽었다 → 1.5초 유지 판정으로 고치고, 고치기 전 결과는 모두 폐기했다.
- **오검출 시뮬레이터가 비현실적**: 정지 중에도 다가오는 가짜 객체를 만들어 정지 중 위험 채널의 62%가 가짜였다. 모델이 "정지 중 위험도는 가짜"라고 배워 버렸다 → 실제 검출기처럼 '정지된 잡음'으로 고쳤더니, 처음 보였던 오검출 조건의 모델 우위가 **사라졌다**. 유리한 결과를 버리고 현실적인 설정을 택했다.
- **수치 손 옮김 사고**: 위험 정의를 3초→5초로 바꾼 뒤 문서에 옛 수치(5.3%)가 남아 있었다 → 이후 모든 표·논문 수치는 결과 파일에서 스크립트로 생성.
- **가설이 깨졌을 때**: "열화가 완만하다"는 가설이 확인되지 않자 결과를 비틀지 않고 "수준 차이"로 주장을 바꿔 서술했다.
